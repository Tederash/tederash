# Starter Repository Audit

Reconciliation of `AGENTS.MD` §0.1 against the initial `next-chrome-starter` repository.

| # | Question | Finding | Resolution |
|---|---|---|---|
| 1 | TypeScript or JavaScript? Next version & router? | Plain JavaScript (`.js`), Next.js `^13.4.1`, React `^18.2.0`, **Pages Router** (`pages/_app.js`, `pages/index.js`). Root-level `pages/`, `components/`, `styles/`, `public/`. No `tsconfig.json`. | Add `tsconfig.json` (`strict: true`, `allowJs: true`) so existing `.js` files remain valid while all new code in `src/` and new pages are strict TypeScript. |
| 2 | Next export config & output dir? | No `next.config.js` was present; `package.json` runs `next build && next export` outputting to `out/`. Package manager in use is `pnpm` (`11.3.0`, `pnpm-lock.yaml`). | Add `next.config.js` with `output: 'export'` and `images: { unoptimized: true }` so static export works reliably without API routes or SSR. |
| 3 | `_next` rename & MV3 CSP? | `out.js` rewrites `/_next` → `./next` in `out/**/*.html` and renames `out/_next` → `out/next`. Inspection of `out/index.html` confirms external deferred `<script src="./next/static/...">` tags and JSON-only `<script id="__NEXT_DATA__" type="application/json">` (no inline executable JS). | Replace `out.js` with `scripts/postbuild-next.mjs` that handles relative path depth (`./next` for root pages, `../next` for nested pages like `onboarding/sandbox.html`) and fails the build if any inline executable `<script>` is emitted. |
| 4 | Where is `manifest.json`? | Static `public/manifest.json` (`manifest_version: 3`, `default_popup: "index.html"`, `host_permissions: ["<all_urls>"]`, `content_scripts` pointing to `inject.js`). | Move to `src/extension/manifest.base.json` + `public/_locales/en/messages.json` and generate `out/manifest.json` via `scripts/build-manifest.mjs`. Remove static `public/manifest.json` after migration so `out/manifest.json` is never overwritten by stale static copy. |
| 5 | Service worker & content scripts? | Only a 1-line `public/inject.js` existed. No service worker, no offscreen document, and no bundler for extension scripts. | Add `scripts/build-extension.mjs` using `esbuild` to bundle `background.js` (ESM), `content.js` (single self-contained IIFE), `offscreen.js` (IIFE), and `main-world.js` (IIFE). |
| 6 | Tailwind or UI component library? | Neither was installed; plain CSS (`styles/globals.css`, `styles/Pages.module.css`) only. | Install Tailwind CSS (`^3.4`), PostCSS, Autoprefixer, and `@radix-ui/*` accessible primitives with CSS variables in `src/styles/tokens.css`. |
| 7 | Existing routes? | Only `pages/index.js` switching `<Index />` and `<New />` via local React state. | Add dedicated routes: `pages/popup.tsx` (plus `pages/index.tsx` as popup alias/landing), `pages/options.tsx` (dashboard), `pages/onboarding.tsx`, `pages/onboarding/sandbox.tsx`, and `pages/sidepanel.tsx`. |
| 8 | Lint & test setup? | None present (`eslint`, `vitest`, `playwright`, `axe` absent). | Add ESLint (`eslint-plugin-jsx-a11y`), Vitest (`jsdom`), Playwright, and `@axe-core/playwright`. |

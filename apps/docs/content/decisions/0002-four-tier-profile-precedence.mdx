---
title: "ADR-0002: Four-tier profile resolution precedence"
---

## Status
Accepted

## Date
2026-11-13

## Context
Accessibility preferences can come from four different sources simultaneously: the framework's baseline defaults, application-level defaults chosen by the developer, the active user profile switched at runtime, and component-level overrides scoped to a sub-tree. When two sources conflict, behavior must be predictable — unpredictable accessibility behavior is worse than none, because users cannot trust the interface.

## Decision
`resolveProfile(frameworkDefault, appDefaults, activeProfile, componentOverride)` merges deep partials with fixed precedence, highest last:

1. Component-level override
2. Active profile
3. Application-level defaults
4. Framework defaults

Merging is key-by-key within each section (`deepMerge`): an override of `visual.fontScale` wins, but every other key of the active profile survives. `updatePreferences` merges into the active profile the same way, enabling fine-tuning (e.g. raising font scale on top of a preset) without discarding preset values.

## Alternatives Considered

### Single-source profile (no overrides)
- Pros: Simplest possible model.
- Cons: Components cannot locally adjust (e.g. a chart needing larger targets); application defaults would fight user profiles.
- Rejected: Too rigid for real applications.

### Last-write-wins mutation
- Pros: Trivial implementation.
- Cons: Order-dependent; switching profiles would clobber user fine-tuning; impossible to reason about in tests.
- Rejected: Predictability is the primary requirement.

### CSS-only layering (media queries / cascade)
- Pros: Zero JavaScript.
- Cons: Cannot express non-visual adaptations (announcements, guided flows, speech), and the cascade's specificity rules are exactly the kind of implicit behavior this framework exists to replace.
- Rejected: Out of scope for an adaptation engine.

## Consequences
- Adaptation output is deterministic and unit-testable (`resolveProfile` and `resolveAdaptations` are pure functions).
- `AccessibilityOverride` (tier 1) lets developers adjust a sub-tree without touching global state.
- Contributors must not add ad-hoc precedence logic inside components; all merging happens in `resolveProfile`.

# TederashInput

`TederashInput` (also exported as `AccessibleInput`) provides an accessible form text input. It manages accessible names (`label`), descriptive helper texts (`aria-describedby`), simplified cognitive instructions (`simplifiedDescription`), and accessible error states (`aria-invalid`).

## Usage

```tsx
import { TederashInput } from "@tederash/components";

export function InputExample() {
  const [email, setEmail] = React.useState("");

  return (
    <TederashInput
      label="Corporate Email"
      type="email"
      value={email}
      onChange={(e) => setEmail(e.target.value)}
      description="Enter your company email for identity verification."
      simplifiedDescription="Type your email address."
      error={!email.includes("@") ? "Email address must include an @ symbol." : undefined}
      required
    />
  );
}
```

## Props Reference

`TederashInput` extends `React.InputHTMLAttributes<HTMLInputElement>` (omitting native `size`).

| Property | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `label` | `string` | Recommended | Visible label associated with the input through `htmlFor` and `id`. It is the accessible name — screen reader comprehension depends on it. |
| `description` | `string` | No | Explanatory helper text associated with the input through `aria-describedby`. |
| `simplifiedDescription` | `string` | No | Alternative plain-language instruction shown automatically when the active profile has `cognitive.simplifiedLanguage` enabled. |
| `error` | `string` | No | Error message displayed below the input. When present, automatically links via `aria-describedby`, sets `aria-invalid="true"`, and applies high-visibility destructive borders. |
| `visuallyHideLabel` | `boolean` | No | When true, visually hides the label using `sr-only` while maintaining programmatic accessibility for screen readers. |
| `required` | `boolean` | No | Marks the input as required, adds a visible required asterisk `*`, and sets `aria-required="true"`. |
| `disabled` | `boolean` | No | Disables user interaction and applies accessible muted styling. |
| `className` | `string` | No | Additional CSS class names merged with default styles. |
| `id` | `string` | No | Explicit HTML id. If omitted, a unique deterministic React id is generated automatically. |
| `speechInput` | `boolean` | No | Opts this field in to voice dictation. The microphone button appears only when the user's profile also enables `speech.speechInput` (e.g. the **Voice Assistance** preset). Never shown for `password`, number/date-like types, or disabled/read-only fields. |
| `speechOutput` | `boolean` | No | Opts this field in to read-aloud of its label, required state, current instructions and error. The speaker button appears only when the user's profile also enables `speech.speechOutput`. |

## Runtime Adaptations

- **Touch Target Sizing**: Automatically adjusts input height to `44px`, `48px`, or `56px` to ensure effortless targeting for motor-impaired users.
- **Cognitive Guidance**: Replaces dense corporate explanations with plain-language `simplifiedDescription` when cognitive support is activated.
- **High-Contrast Indicators**: Highlights borders and active focus rings with enhanced contrast ratios under low-vision profiles.

## Voice Dictation & Read-Aloud

Two switches must both be on for a button to appear:

1. **The developer opts the field in** with `speechInput` and/or `speechOutput`.
2. **The user's profile enables the feature** (`speech.speechInput` / `speech.speechOutput`). The built-in **Voice Assistance** preset (`VOICE_ASSIST_PRESET`) turns both on. Users can also enable them on top of another preset with `updatePreferences({ speech: { speechInput: true } })`.

```tsx
<TederashInput label="Full name" speechInput speechOutput />
```

Buttons are also hidden when the browser lacks the Web Speech API, and the speech hooks are only mounted while a feature is actually on.

- **Review before insert**: dictated text never goes straight into the field. When listening stops, a panel shows what was heard in an editable box, plus up to four other matches the engine considered (useful for names like "Abebe Bikila" that recognizers often mishear). The user can edit, pick a match, **Insert** / **Replace** (or press <kbd>Enter</kbd>), **Try again**, or **Discard** (<kbd>Escape</kbd>). Focus moves into the panel when it opens and returns to the field after confirming.
- **Email and phone fields** (`type="email"` / `type="tel"`): spoken symbols are converted ("at" → `@`, "dot" → `.`, "underscore", "dash", "plus"), letters spelled one at a time are joined ("h e n o k" → `henok`), number words become digits, and valid-looking addresses/numbers are listed first. A tip explains how to speak the value. The conversion understands English spoken forms only. Exposed from core as `normalizeDictation` / `rankDictationCandidates`.
- **Replaces after confirmation**: the reviewed text replaces the field's contents and goes through the normal `onChange` path, so controlled and uncontrolled fields both work. When the field already has text, the button reads **Replace** and the panel warns that the current text will be replaced. `maxLength` is respected.
- **Spelling letter by letter** works in every field: runs of single spoken letters are joined ("Abebe B I K I L A" → "Abebe Bikila"; a run spoken in capitals is title-cased when longer than 3 letters, so "U N" stays "UN"). Lone words like "I" or "a" are untouched. A tip in the panel suggests this for unusual names.
- **Language and rate** come from `profile.speech.language` (e.g. `am-ET`) and `profile.speech.speechRate`. Browser support for Amharic recognition and synthesis varies, so test on your target devices.
- **Feedback**: start, the heard text, insertion, discard and failure are each announced once through the live region. Interim text appears visually under the field but is hidden from screen readers to avoid noise. If recognition fails (no microphone, permission denied, unsupported language), the user is told to type instead.
- **Privacy**: some browsers (e.g. Chrome) send dictation audio to a cloud speech service. Dictation only starts when the user presses the microphone button.

# TederashInput

`TederashInput` (also exported as `AccessibleInput`) provides an accessible form text input. It manages accessible names (`label`), descriptive helper texts (`aria-describedby`), simplified cognitive instructions (`simplifiedDescription`), and accessible error states (`aria-invalid`).

## Usage

```tsx
import { TederashInput } from "@tederash/components";

export function InputExample() {
  const [email, setEmail] = React.useState("");

  return (
    <TederashInput
      label="Corporate Email"
      type="email"
      value={email}
      onChange={(e) => setEmail(e.target.value)}
      description="Enter your company email for identity verification."
      simplifiedDescription="Type your email address."
      error={!email.includes("@") ? "Email address must include an @ symbol." : undefined}
      required
    />
  );
}
```

## Props Reference

`TederashInput` extends `React.InputHTMLAttributes<HTMLInputElement>` (omitting native `size`).

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `label` | `string` | `undefined` | Visible label associated with the input through `htmlFor` and `id`. Essential for accessible names and screen reader comprehension. |
| `description` | `string` | `undefined` | Explanatory helper text associated with the input through `aria-describedby`. |
| `simplifiedDescription` | `string` | `undefined` | Alternative plain-language instruction shown automatically when the active profile has `cognitive.simplifiedLanguage` enabled. |
| `error` | `string` | `undefined` | Error message displayed below the input. When present, automatically links via `aria-describedby`, sets `aria-invalid="true"`, and applies high-visibility destructive borders. |
| `visuallyHideLabel` | `boolean` | `false` | When true, visually hides the label using `sr-only` while maintaining programmatic accessibility for screen readers. |
| `required` | `boolean` | `false` | Marks the input as required, adds a visible required asterisk `*`, and sets `aria-required="true"`. |
| `disabled` | `boolean` | `false` | Disables user interaction and applies accessible muted styling. |
| `className` | `string` | `undefined` | Additional CSS class names merged with default styles. |
| `id` | `string` | `useId()` | Explicit HTML id. If omitted, a unique deterministic React id is generated automatically. |
| `speechInput` | `boolean` | `false` | Opts this field in to voice dictation. The microphone button appears only when the user's profile also enables `speech.speechInput` (e.g. the **Voice Assistance** preset). Never shown for `password`, number/date-like types, or disabled/read-only fields. |
| `speechOutput` | `boolean` | `false` | Opts this field in to read-aloud of its label, required state, current instructions and error. The speaker button appears only when the user's profile also enables `speech.speechOutput`. |

## Runtime Adaptations

- **Touch Target Sizing**: Automatically adjusts input height to `44px`, `48px`, or `56px` to ensure effortless targeting for motor-impaired users.
- **Cognitive Guidance**: Replaces dense corporate explanations with plain-language `simplifiedDescription` when cognitive support is activated.
- **High-Contrast Indicators**: Highlights borders and active focus rings with enhanced contrast ratios under low-vision profiles.

## Voice Dictation & Read-Aloud

Two switches must both be on for a button to appear:

1. **The developer opts the field in** with `speechInput` and/or `speechOutput`.
2. **The user's profile enables the feature** (`speech.speechInput` / `speech.speechOutput`). The built-in **Voice Assistance** preset (`VOICE_ASSIST_PRESET`) turns both on. Users can also enable them on top of another preset with `updatePreferences({ speech: { speechInput: true } })`.

```tsx
<TederashInput label="Full name" speechInput speechOutput />
```

Buttons are also hidden when the browser lacks the Web Speech API, and the speech hooks are only mounted while a feature is actually on.

- **Review before insert**: dictated text never goes straight into the field. When listening stops, a panel shows what was heard in an editable box, plus up to four other matches the engine considered (useful for names like "Abebe Bikila" that recognizers often mishear). The user can edit, pick a match, **Insert** (or press <kbd>Enter</kbd>), **Try again**, or **Discard** (<kbd>Escape</kbd>). Focus moves into the panel when it opens and returns to the field after inserting.
- **Appends, never overwrites**: inserted text is added after what the user already typed and is sent through the normal `onChange` path, so controlled and uncontrolled fields both work. `maxLength` is respected.
- **Language and rate** come from `profile.speech.language` (e.g. `am-ET`) and `profile.speech.speechRate`. Browser support for Amharic recognition and synthesis varies, so test on your target devices.
- **Feedback**: start, the heard text, insertion, discard and failure are each announced once through the live region. Interim text appears visually under the field but is hidden from screen readers to avoid noise. If recognition fails (no microphone, permission denied, unsupported language), the user is told to type instead.
- **Privacy**: some browsers (e.g. Chrome) send dictation audio to a cloud speech service. Dictation only starts when the user presses the microphone button.
